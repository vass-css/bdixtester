## Executive decision

**MINOR TARGETED IMPROVEMENTS RECOMMENDED. NO REDESIGN REQUIRED.**

Preserve the current visual identity, screen layouts, navigation and features. The verified opportunities are small copy/state and Bengali localization corrections, not evidence for a broad redesign. The core scan task is already reachable from Home and Servers; only the separate `ScanScreen` composable is not connected to root navigation. Do not add a tab or route absent evidence that the existing scan entry is inadequate.

Severity and priority are separate: Critical 0, High 0, Medium 2, Low 8, Informational 8; P0 0, P1 0, P2 3, P3 15. These are conservative research-triage classifications, not measured population impact.

## Classification rules

Evidence class describes what is established, not the importance of a concern:

- `CONFIRMED`: directly demonstrated by current source, test, or reproducible evidence.
- `PARTIALLY_CONFIRMED`: a code fact is established but the full user-facing claim or impact is not.
- `UNVERIFIED`: needs a device, assistive-technology, performance, or user study.
- `NOT_A_DEFECT`: the concern was checked and available evidence does not establish a defect.
- `OPTIONAL_IMPROVEMENT`: a plausible enhancement; not a confirmed defect.

Severity describes the supported consequence: Critical, High, Medium, Low, or Informational. Priority describes action sequencing: P0, P1, P2, or P3. No Critical/High or P0/P1 issue is substantiated. P2 is reserved for targeted localization and a misleading filtered-history empty state; P3 is low-impact, optional, documentation-only, or test-gate work.

Confidence is High for directly inspected implementation/resource facts, Medium where product meaning or consequence is uncertain, and Low where a device/user observation is absent. Code facts do not establish user confusion, frequency, accessibility conformance, or runtime performance.
