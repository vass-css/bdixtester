## CI Observability Artifacts

The Android CI workflow retains the following diagnostic outputs for 14 days:

- `app/build/test-results/testDebugUnitTest/`: Gradle JUnit XML, including one `<testcase>` element per executed test and its `time` attribute in seconds.
- `app/build/reports/tests/testDebugUnitTest/` and the rest of `app/build/reports/`: HTML test reports, lint reports, and diagnostics.
- `build/reports/profile/profile-<timestamp>.html`: Gradle `--profile` report for startup/configuration/task timing.
- `app/build/reports/test-method-timings.csv`: one row per expected or observed test case. Columns are `test_class`, `test_method`, `duration_seconds`, `status`, and `failure_information`. Status is `PASSED`, `FAILED`, `SKIPPED`, `MISSING`, `ERROR`, or `UNEXPECTED`; a missing result has an empty duration and is never treated as passed.
- `app/build/reports/benchmark-metrics.csv`: parsed `[PERF_BENCH]` output with `test_class`, `metric`, and `value` columns. Gradle stores test stdout at suite level, so this file does not infer a test-method association for those metrics.
- `app/build/outputs/apk/debug/`: existing debug APK artifact.

The performance-only workflow filters the timing report to `PerformanceBenchmarkTest`; push, pull-request, and manual full-suite runs inventory all test methods. The workflow concurrency key separates event type, ref, and selected suite: a manual run cannot cancel a push or pull-request run, while a newer run for the same event/ref/suite can still cancel its superseded predecessor.
